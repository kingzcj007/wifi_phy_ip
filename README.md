# WIFI PHY IP

WiFi PHY IP 芯片项目根目录。本仓库只描述目录边界与协作约定，不存放具体设计产物本身的分发件。

## 一级目录用途与边界

| 目录 | 放什么 | 不放什么 |
| --- | --- | --- |
| `00_project/` | 项目计划、评审记录、会议纪要等项目过程管理文档 | 任何设计、验证、实现文件 |
| `01_spec/` | 系统规格、架构设计、接口协议、寄存器映射等需求与设计规格 | 可执行代码、综合结果 |
| `02_model/` | MATLAB 浮点算法模型、C 模型、定点量化模型等行为级参考模型 | 可综合 RTL、综合与后端产物 |
| `03_rtl/` | 可综合的 RTL 源码，按功能划分 common/tx/rx/agc/regs/top | 仿真激励、波形、log、临时脚本 |
| `04_verif/` | 验证环境、测试用例、覆盖率收集、形式验证 | 可综合 RTL 源码 |
| `05_impl/` | 综合、时序约束、功耗、DFT、物理设计等实现阶段产物与脚本 | RTL 源码、验证用例 |
| `06_fpga/` | FPGA 原型验证工程、板级调试与上板记录 | 最终交付冻结件 |
| `07_sw/` | 驱动、固件、寄存器配置与上位机联调软件 | 硬件设计源码 |
| `08_deliver/` | 按版本冻结的对外交付件 | 开发过程中的中间文件 |
| `09_scripts/` | 全流程公共脚本（构建、回归、检查、发布） | 一次性临时脚本、与流程无关的碎片文件 |
| `10_release/` | 正式发布的版本清单、发布说明与打包入口 | 未冻结的开发中内容 |

## 关键约束

1. `03_rtl` 只放可综合源码。仿真激励、测试平台、波形文件（vcd/fst/wlf）、各类 log 一律不得进入该目录，验证代码统一放到 `04_verif`。
2. `02_model/c_model` 是 RTL 位真比对的黄金参考。RTL 与 C 模型出现不一致时，以评审确认后的 C 模型为准；修改 C 模型必须同步更新版本说明并通知验证与 RTL 负责人。
3. `08_deliver` 按版本冻结、只增不改。交付件一旦入库即视为冻结，任何修改都以新版本目录重新交付，禁止就地覆盖历史版本。
4. 脚本统一放 `09_scripts`，禁止在各目录内散落可执行脚本；流程中调用的脚本路径应通过 `09_scripts` 统一入口引用。
5. 所有文本文件使用 UTF-8 编码，内容以中文为主。

## 目录树

```
├── 00_project/{plan,review,meeting}
├── 01_spec/{system,arch,interface,regmap}
├── 02_model/{matlab,c_model,fixed_point}
├── 03_rtl/{common,tx,rx,agc,regs,top}
├── 04_verif/{env,tests,coverage,formal}
├── 05_impl/{syn,constraints,power,dft,pd}
├── 06_fpga/
├── 07_sw/
├── 08_deliver/
├── 09_scripts/
└── 10_release/
```

各空目录通过 `.gitkeep` 占位以纳入版本管理；本目录当前未初始化 git 仓库。
